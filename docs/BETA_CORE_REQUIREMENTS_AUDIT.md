# BETA 核心需求核查

核查日期：2026-09-17。范围：用户与运营在本任务中提出的核心业务诉求、当前源代码、历史验收记录和本轮针对性检查。

## 结论

目前是可操作的BETA原型，不能认定运营核心诉求全部完成。最关键的缺口不是少几个页面，而是“组合需求支持什么改款”尚未贯通；推荐解释与生图指令存在脱节；自动生图失败会再次提交。适合继续确认流程和需求，不适合据此宣称能可靠找出市场空白或已经完成业务验收。

“已接入”表示有实际调用代码，“历史验证”表示过去确实留下结果，不等于今天上游仍正常；“未验收”不等于未实现，也不等于已通过。

## 优先级与验收门槛

### P0：先保证不会错误重复提交

自动失败停止、任务恢复和明确手动重试；同一报告同一方案只有一次自动创建，接口503时不会周期提交。不要把“可能重复提交”直接说成已重复扣费，后端已有任务可能去重，需按任务记录判断费用。

### P1：把运营最核心的第三步接到改款

1. 少量组合的独立关键词证据进入方案生成，不再在最后过滤掉组合。
2. 同期同口径比较，只对有数据的方向给相对优先级；没数据的保留为设计假设，不叫空白机会。
3. 统一方案中的原款、部位、改动、保留项、需求组、参考商品；模型解释、自动生图、自定义图说明都引用正确版本。
4. 允许纠正关键原款特征，并让候选词与建议失效重算，避免“原款已有还推荐新增”。

验收：一份报告中能从推荐改动追到组合查询与原始词数据，生成图执行的是同一改动；改变自定义方向后旧需求不被当成新证据。

### P2：清理会误导运营的展示

统一缺失状态、隐藏无值属性组、修正面料图门槛、按类目切换设计维度；把字段覆盖与结论可信度分开。评论痛点若仍要求作为首版核心依据，需要单独补齐来源和引用，不靠模型猜。

## 本轮证据与检查边界

- `scripts/verify-search-resilience.cjs`通过：并发请求合并、失败冷却、备用通道、缓存恢复及拒绝非商品详情页；包含既有设计规则回归。使用测试输入，不是今日真实市场数据。
- `scripts/audit-core-needs.cjs`：拦截生图接口返回503，3张卡片约4.2秒内发出12次POST，确认自动再次提交。所有生图请求在浏览器内拦截，没有调用上游或扣费。
- 公网 `/api/health` 返回200，仅证明演示服务可达，不证明Amazon、西柚或模型都可用。
- 历史 `targeted-*.json` 三份结果（男士西裤、女士泡泡长袖衬衫、女士夏裙），日期为2026-09-09，均是9款商品子集，方案数3/3/2，关键词有效数8/13/9。有模型解释结果；不能作为今天完整三页与三张生图闭环的验收凭据。
- 本轮没有重新调用收费模型/MCP/生图，没有以旧报告冒充新采集。没有找到覆盖当前全部核心要求的完整新报告验收证据。
